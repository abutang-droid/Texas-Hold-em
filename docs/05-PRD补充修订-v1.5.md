## 一、场次系统补充（§4 修订）

### 4.2.1 官方场桌配置 【新增】

- **座位数**：固定 **6 人桌**
- **开局条件**：≥ **2 人** seated 即可发牌（Heads-up 合法）
- **观战**：v1.0 **不支持**观战

### 4.3.1 动态带入上限公式 【明确】

设 `T = 100 × 2^n`（n = 0, 1, 2, …）

当桌内 **≥ 2 名**玩家（含 Bot）当前筹码 **严格大于** `T` 时，新玩家/破产重带入的上限提升至 `100 × 2^(n+1)`。

| n | 触发条件（≥2人筹码 >） | 带入上限 |
|---|---|---|
| 0 | — | 100 |
| 1 | 500 | 200 |
| 2 | 1,000 | 400 |
| 3 | 2,000 | 800 |
| 4 | 4,000 | 1,600 |
| … | 继续翻倍 | 继续翻倍 |

已在桌玩家不受上限约束，筹码可自然增长。

### 4.5.1 快速开始匹配流程 【细化】

1. 玩家点击「快速开始」
2. 匹配服务查找 `status=PLAYING|WAITING` 且 **真实玩家 ≥ 2** 的官方场
3. 找到 → 分配座位；找不到 → 创建新桌
4. 新桌创建后启动 **5 秒计时器**
5. 若 5 秒后真实玩家 < 3 → 补入 Bot 至 3 人（单桌 Bot ≤ 4，至少 1 真实玩家）
6. 真实玩家加入满 6 人 → 下局开始前 Bot 自然退场

### 4.4.6 私人场补充 【新增】

- **人数**：2–9 人，建房时选择
- **解散投票**：房主发起后，所有 seated 玩家需在 **60 秒**内同意；离线/超时视为拒绝
- **Re-buy 审批超时**：60 秒未响应自动拒绝
- **聊天**：支持 **文字**；v1.0/v1.5 **不支持语音**
- **禁言**：仅 **文字禁言**（删除原「语音禁言」表述）

## 二、经济规则补充（§2 修订）

### 2.2.1 支付渠道优先级 【明确】

| 版本 | 渠道 |
|---|---|
| v1.0 MVP | Apple IAP、Google Play Billing |
| v1.1 | Web 端 Stripe / USDC（World App） |

### 2.5 筹码精度 【新增】

- 全产品 **仅使用整数筹码**
- UI 不展示小数；计算一律 **向下取整**（抽水等同）

---

## 三、对战规则补充（§5 修订）

### 5.2.1 官方场聊天 【新增】

- 官方场：仅 **Emoji 快捷语**（预设 8–12 个），无自由文字
- 私人场：自由文字 + Emoji

### 5.6 奇数筹码分配 【明确】

Chop 时无法整除的 1 筹码分配给：**庄家（Button）顺时针方向第一个未弃牌且仍在争夺该池的玩家**。

---

## 四、Bot 机制补充（§6 修订）

### 6.1.1 退场规则 【明确】

- Bot 收到退场指令后，**必须完成当前手牌**（含 All-in 摊牌）
- 不得在行动中途消失

### 6.5 Bot 预算 【新增默认值】

- 全服 Bot 日亏损预算默认：**500,000 筹码**
- 达上限后 Bot 只 Check/Fold，后台告警

---

## 五、技术规格修正（§10 修订）

### 10.1 持久化策略 【修正 — 替换原「每次操作后持久化」】

| 时机 | 存储 |
|---|---|
| 对局中每次行动 | Redis 更新 |
| 每手牌结束 | 异步写 `hand_histories` + rake 流水 |
| 玩家离桌/房间解散 | MySQL 事务写回筹码余额 |
| 带入 | MySQL 事务扣款 + Redis 注入 |

## 六、版本规划修订（§11 修订）

### v1.0 MVP 范围 【明确边界】

**包含**：
- 官方场（6 人桌、1/2 盲注、动态 cap、5% rake）
- 用户（Apple/Google + 游客）
- 商城（IAP 双端）
- Bot GTO 补位
- IP/设备互斥
- 断线重连
- 后台最小集

**不包含（v1.5）**：
- 私人定制场
- 好友 / 排行榜 / 成就
- 对局回放 UI
- 运营活动 CMS
