# 数据库设计完整版

| 项目 | 内容 |
|---|---|
| 版本 | v2.0 |
| 依据 | PRD v2.1 |
| 存储 | **PostgreSQL 16**（持久化）+ Redis Cluster（热状态） |
| 变更 | MySQL → PostgreSQL；新增 `preferred_locale`；JSONB 替代 JSON |

---

## 一、设计原则

1. **筹码只用整数**：`BIGINT` + `CHECK (>= 0)`，禁止浮点
2. **流水即真相**：`users.chips_balance` 为缓存字段，审计以 `chip_transactions` 汇总为准
3. **对局内热、对局外冷**：进行中状态在 Redis；每手牌结束写 `hand_histories`；离桌写回余额
4. **所有筹码变动必须有流水**：充值、抽水、输赢、权限费、赠送、管理员调整
5. **国际化**：用户语言偏好存 `users.preferred_locale`

```sql
CREATE TYPE account_type AS ENUM ('GUEST', 'REGISTERED');
```

### 2.2 用户与认证

#### `users` — 用户主表

```sql
CREATE TABLE users (
    id                      BIGSERIAL PRIMARY KEY,
    account_type            account_type NOT NULL DEFAULT 'GUEST',
    oauth_provider          oauth_provider NULL,
    oauth_sub               VARCHAR(128) NULL,
    device_id               VARCHAR(128) NULL,
    nickname                VARCHAR(32) NOT NULL,
    avatar_url              VARCHAR(512) NULL,
    chips_balance           BIGINT NOT NULL DEFAULT 0 CHECK (chips_balance >= 0),
    total_exp               INTEGER NOT NULL DEFAULT 0 CHECK (total_exp >= 0),
    level                   SMALLINT NOT NULL DEFAULT 1 CHECK (level >= 1),
    preferred_locale        VARCHAR(10) NOT NULL DEFAULT 'en-US',
    private_room_permission BOOLEAN NOT NULL DEFAULT FALSE,
    private_room_permission_at TIMESTAMPTZ NULL,
    status                  user_status NOT NULL DEFAULT 'ACTIVE',
    settings_json           JSONB NULL,
    created_at              TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at              TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    CONSTRAINT uk_oauth UNIQUE (oauth_provider, oauth_sub),
    CONSTRAINT chk_preferred_locale CHECK (preferred_locale IN ('zh-CN', 'en-US'))
);

CREATE INDEX idx_users_device ON users (device_id);
CREATE INDEX idx_users_status ON users (status);
```

#### `user_sessions` — Refresh Token

```sql
CREATE TABLE user_sessions (
    id                  BIGSERIAL PRIMARY KEY,
    user_id             BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    refresh_token_hash  VARCHAR(64) NOT NULL,
    device_info         VARCHAR(256) NULL,
    expires_at          TIMESTAMPTZ NOT NULL,
    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_user_sessions_user ON user_sessions (user_id);
```

### 2.3 筹码与经济

#### `chip_transactions` — 筹码流水

```sql
CREATE TABLE chip_transactions (
    id              BIGSERIAL PRIMARY KEY,
    user_id         BIGINT NOT NULL REFERENCES users(id),
    amount          BIGINT NOT NULL,
    balance_after   BIGINT NOT NULL CHECK (balance_after >= 0),
    type            chip_tx_type NOT NULL,
    reference_id    VARCHAR(64) NULL,
    meta_json       JSONB NULL,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_chip_tx_user_time ON chip_transactions (user_id, created_at DESC);
CREATE INDEX idx_chip_tx_type ON chip_transactions (type);
CREATE INDEX idx_chip_tx_ref ON chip_transactions (reference_id);
```

#### `recharge_orders` — 充值订单

```sql
CREATE TABLE recharge_orders (
    id              BIGSERIAL PRIMARY KEY,
    order_no        VARCHAR(32) NOT NULL UNIQUE,
    user_id         BIGINT NOT NULL REFERENCES users(id),
    amount_fiat     NUMERIC(12, 2) NOT NULL,
    amount_chips    BIGINT NOT NULL CHECK (amount_chips >= 0),
    gift_chips      BIGINT NOT NULL DEFAULT 0 CHECK (gift_chips >= 0),
    channel         recharge_channel NOT NULL,
    channel_tx_id   VARCHAR(128) NULL,
    status          recharge_status NOT NULL DEFAULT 'PENDING',
    paid_at         TIMESTAMPTZ NULL,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_recharge_user ON recharge_orders (user_id);
CREATE INDEX idx_recharge_status ON recharge_orders (status);
```

#### `daily_recharge_stats`

```sql
CREATE TABLE daily_recharge_stats (
    user_id         BIGINT NOT NULL REFERENCES users(id),
    stat_date       DATE NOT NULL,
    total_chips     BIGINT NOT NULL DEFAULT 0 CHECK (total_chips >= 0),
    PRIMARY KEY (user_id, stat_date)
);
```

## 三、Redis 数据结构

（与 v1.1 相同，无变更）

| Key | Type | 用途 |
|---|---|---|
| `room:state:{room_id}` | JSON String | 房间实时状态 |
| `user:session:{user_id}` | Hash | 会话映射 |
| `lock:buy_in:{user_id}` | String | 带入锁 |
| `lb:profit:week` | ZSET | 周盈利榜 |

## 四、筹码生命周期

```
[充值]
  → PostgreSQL 事务: recharge_orders + chip_transactions + users

[带入]
  → PG 事务扣款 + Redis 注入座位筹码

[对局中]
  → 仅 Redis

[每手牌结束]
  → INSERT hand_histories + rake 流水

[离桌]
  → PG 事务写回 chips_balance + CASH_OUT 流水
```

## 五、PostgreSQL 选型说明

| 优势 | 说明 |
|---|---|
| JSONB | `actions_json` / `settings_json` 高效查询与索引 |
| 事务与 MVCC | 筹码事务强一致 |
| 分区表 | v1.5+ `hand_histories` 按月 `PARTITION BY RANGE` |
| 扩展性 | Citus / 读写分离成熟 |
