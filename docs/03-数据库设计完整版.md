# 数据库设计完整版

| 项目 | 内容 |
|---|---|
| 版本 | v1.1 |
| 依据 | PRD v1.4 + 评审补充 v1.5 |
| 存储 | MySQL 8.0（持久化）+ Redis Cluster（热状态） |
| 变更 | chips 改 BIGINT；补全好友/等级/充值/成就/后台配置表 |

---

## 一、设计原则

1. **筹码只用整数**：`BIGINT UNSIGNED`，禁止浮点
2. **流水即真相**：`users.chips_balance` 为缓存字段，审计以 `chip_transactions` 汇总为准
3. **对局内热、对局外冷**：进行中状态在 Redis；每手牌结束写 `hand_histories`；离桌写回余额
4. **所有筹码变动必须有流水**：充值、抽水、输赢、权限费、赠送、管理员调整

## 二、MySQL 表结构

### 2.1 用户与认证

#### `users` — 用户主表

```sql
CREATE TABLE users (
    id              BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
    account_type    ENUM('GUEST','REGISTERED') NOT NULL DEFAULT 'GUEST',
    oauth_provider  ENUM('APPLE','GOOGLE','FACEBOOK') NULL,
    oauth_sub       VARCHAR(128) NULL,
    device_id       VARCHAR(128) NULL COMMENT '设备指纹，游客绑定/反作弊',
    nickname        VARCHAR(32) NOT NULL,
    avatar_url      VARCHAR(512) NULL,
    chips_balance   BIGINT UNSIGNED NOT NULL DEFAULT 0,
    total_exp       INT UNSIGNED NOT NULL DEFAULT 0,
    level           SMALLINT UNSIGNED NOT NULL DEFAULT 1,
    private_room_permission TINYINT(1) NOT NULL DEFAULT 0,
    private_room_permission_at DATETIME NULL,
    status          ENUM('ACTIVE','FROZEN','BANNED') NOT NULL DEFAULT 'ACTIVE',
    settings_json   JSON NULL COMMENT '隐身模式等偏好',
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_oauth (oauth_provider, oauth_sub),
    KEY idx_device (device_id),
    KEY idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

#### `user_sessions` — 登录会话（可选，Refresh Token 管理）

```sql
CREATE TABLE user_sessions (
    id              BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
    user_id         BIGINT UNSIGNED NOT NULL,
    refresh_token_hash VARCHAR(64) NOT NULL,
    device_info     VARCHAR(256) NULL,
    expires_at      DATETIME NOT NULL,
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    KEY idx_user (user_id),
    FOREIGN KEY (user_id) REFERENCES users(id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

### 2.2 筹码与经济

#### `chip_transactions` — 筹码流水（审计核心）

```sql
CREATE TABLE chip_transactions (
    id              BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
    user_id         BIGINT UNSIGNED NOT NULL,
    amount          BIGINT NOT NULL COMMENT '正增负减',
    balance_after   BIGINT UNSIGNED NOT NULL COMMENT '变动后余额快照',
    type            ENUM(
        'RECHARGE',           -- 充值
        'EVENT_GIFT',         -- 运营赠送
        'RAKE',               -- 抽水（系统回收，玩家视角为负或记录关联）
        'GAME_WIN',
        'GAME_LOSS',
        'PRIVATE_FEE',        -- 私人场权限费 100
        'BUY_IN',             -- 带入离桌
        'CASH_OUT',           -- 离桌退回
        'ADMIN_ADJUST'        -- 后台人工调整
    ) NOT NULL,
    reference_id    VARCHAR(64) NULL COMMENT 'hand_id / order_id / room_id',
    meta_json       JSON NULL COMMENT '扩展：rake比例、room_type等',
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    KEY idx_user_time (user_id, created_at),
    KEY idx_type (type),
    KEY idx_ref (reference_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

#### `recharge_orders` — 充值订单

```sql
CREATE TABLE recharge_orders (
    id              BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
    order_no        VARCHAR(32) NOT NULL UNIQUE,
    user_id         BIGINT UNSIGNED NOT NULL,
    amount_fiat     DECIMAL(12,2) NOT NULL COMMENT '法币金额',
    amount_chips    BIGINT UNSIGNED NOT NULL COMMENT '1:1 筹码',
    gift_chips      BIGINT UNSIGNED NOT NULL DEFAULT 0 COMMENT '运营赠送部分',
    channel         ENUM('APPLE_IAP','GOOGLE_PLAY','STRIPE','USDC') NOT NULL,
    channel_tx_id   VARCHAR(128) NULL COMMENT '渠道交易号',
    status          ENUM('PENDING','PAID','FAILED','REFUNDED') NOT NULL DEFAULT 'PENDING',
    paid_at         DATETIME NULL,
    created_at      DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    KEY idx_user (user_id),
    KEY idx_status (status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

#### `daily_recharge_stats` — 单日充值限额（50,000）

```sql
CREATE TABLE daily_recharge_stats (
```

## 三、Redis 数据结构

### 3.1 房间状态（核心）

```
Key:    room:state:{room_id}
Type:   Hash / JSON String
TTL:    无（房间关闭时 DEL）
```

**JSON 结构示例**：

```json
{
  "roomId": "R123456",
  "roomType": "OFFICIAL",
  "phase": "FLOP",
  "handId": "H20260705143000001",
  "buttonSeat": 2,
  "communityCards": ["Ah", "Kd", "7c"],
  "pots": [{ "amount": 45, "eligibleSeats": [0, 1, 3] }],
  "sidePots": [],
  "currentTurnSeat": 3,
  "actionDeadline": 1720195200000,
  "seats": [
    {
      "seatIndex": 0,
      "userId": 10001,
      "isBot": false,
      "chips": 198,
      "betThisRound": 0,
      "status": "ACTIVE",
      "holeCards": ["**", "**"]
    }
  ],
  "buyInCap": 100,
  "rakeRate": 0.05
}
```

> 注意：`holeCards` 在 Redis 存明文，下发 WS 时按玩家过滤。

### 3.2 其他 Key

| Key | Type | 用途 | TTL |
|---|---|---|---|
| `user:session:{user_id}` | Hash | room_id, socket_id, pod_id | 24h |
| `lock:buy_in:{user_id}` | String | 带入分布式锁 | 10s |
| `room:pod:{room_id}` | String | Room Pod 路由 | 随房间 |
| `room:{room_id}:ips` | Set | 同桌 IP 互斥 | 随房间 |
| `room:{room_id}:devices` | Set | 设备指纹互斥 | 随房间 |
| `match:official:queue` | List | 快速开始匹配队列 | - |
| `bot:budget:daily:{date}` | String | 当日 Bot 亏损累计 | 48h |
| `lb:profit:week` | ZSET | 盈利榜缓存 | 7d |
| `lb:bigpot:week` | ZSET | 单局最高榜 | 7d |

## 四、筹码生命周期时序

```
[充值]
  Client → POST /shop/recharge → 渠道回调 → MySQL 事务:
    INSERT recharge_orders + INSERT chip_transactions + UPDATE users.chips_balance

[带入]
  Client → WS join_room → Redis lock → MySQL 事务:
    UPDATE users (扣 chips_balance) + INSERT chip_transactions(BUY_IN) + INSERT room_sessions
  → Redis room:state 增加 seat 筹码

[对局中]
  下注/赢池 → 仅更新 Redis room:state

[每手牌结束]
  → INSERT hand_histories
  → INSERT chip_transactions(RAKE) 系统侧记录
  → 赢家/输家 GAME_WIN/GAME_LOSS 可合并为 session 级，离桌时结算

[离桌]
  MySQL 事务:
    UPDATE room_sessions.cash_out + INSERT chip_transactions(CASH_OUT)
    + UPDATE users.chips_balance
  → DEL Redis seat 数据
```
