## Phase 1：基础设施与核心引擎

**目标**：可独立运行的扑克引擎 + 数据层 + 项目骨架

### 1.1 工程初始化

| 任务 | 产出 | Owner 建议 |
|---|---|---|
| Monorepo 搭建（pnpm workspace） | `apps/mobile`, `apps/api`, `apps/room`, `packages/shared` | 全栈 |
| RN Expo 项目初始化 | 空白大厅 + 导航 | 客户端 |
| NestJS api + room 项目 | 健康检查接口 | 后端 |
| Docker Compose 本地环境 | MySQL + Redis + 服务联调 | DevOps |
| Flyway/Liquibase migration | 核心表 DDL | 后端 |
| ESLint/Prettier/CI 骨架 | GitHub Actions lint | DevOps |

### 1.2 扑克核心引擎（`packages/poker-engine`）

| 任务 | 验收标准 |
|---|---|
| 牌组洗牌（CSPRNG） | Fisher-Yates + crypto.randomBytes |
| 手牌评估（7 选 5） | 覆盖所有牌型，对标 known test vectors |
| 边池算法 | 通过 ≥5 个单元测试场景 |
| 抽水计算 | no-flop-no-drop + floor |
| 行动合法性校验 | fold/check/call/raise/all-in/min-raise |
| XState 状态机 | PRE_FLOP → … → END_HAND 完整流转 |

### 1.3 数据层

| 任务 | 验收标准 |
|---|---|
| users + chip_transactions migration | 本地可 migrate |
| Redis room state 读写封装 | JSON 序列化 + 类型安全 |
| 带入/离桌事务模板 | MySQL 事务 + Redis lock 单测 |

**Phase 1 交付物**：
- [ ] `packages/poker-engine` 测试覆盖率 ≥90%（核心算法）
- [ ] 命令行/demo 可模拟一手完整牌局并输出结算
- [ ] Docker Compose 一键启动

## Phase 2：官方场 MVP

**目标**：客户端可完成真实联网对局（含 Bot）

### 2.1 Room Server

| 任务 | 验收标准 |
|---|---|
| Socket.io 集成 + JWT 鉴权 | 未授权连接拒绝 |
| join_room / player_action 事件 | 符合 WS 协议 v1.0 |
| room_state_sync 快照 | 重连后状态一致 |
| 15 秒倒计时 + 超时处理 | 2 次超时 → Sit Out |
| IP/设备互斥中间件 | 同 IP 第二人 join 被拒 |
| 动态 buy-in cap | 服务端实时计算 |
| END_HAND → hand_histories | 异步写入 |

### 2.2 Match Service

| 任务 | 验收标准 |
|---|---|
| 快速开始 API | 优先 ≥2 真实玩家桌 |
| 新桌 5 秒 Bot 计时器 | <3 人触发补位 |
| Bot 退场逻辑 | 满桌后下局 Bot 离开 |

### 2.3 Bot 集成

| 任务 | 验收标准 |
|---|---|
| Python gRPC 服务骨架 | Decide 接口可用 |
| v1.0 策略：规则型 fallback | gRPC 超时 800ms 降级 |
| Bot 拟人延迟 | 1–5s 随机 think_time |
| Bot 经济隔离 | 不扣真实玩家余额 |

### 2.4 客户端

| 任务 | 验收标准 |
|---|---|
| 拟物化牌桌 UI（6 座） | 座位、筹码、底池 |
| WS 连接 + 状态同步 | 断线重连 |
| 玩家操作面板 | fold/check/call/raise/all-in |
| 发牌/筹码飞入动画 | 基础抛物线动画 |
| 15 秒倒计时 UI | 最后 5 秒红框+音效 |
| 大厅 + 快速开始 | 一键进桌 |

**Phase 2 交付物**：
- [ ] TestFlight / 内测 APK 可完成官方场对局
- [ ] 2 真实玩家 + Bot 混合桌稳定运行 1 小时无 crash
