## 一、架构图修正

**删除** Load Balancer 到 MySQL 的直连。正确路径：

```
Client → LB → API Server  → MySQL / Redis
Client → LB → Room Server → Redis (+ MySQL 异步结算)
              Room Server → Bot Engine (gRPC)
```

---

## 二、服务拆分建议

| 服务 | 职责 | 状态 | 技术 |
|---|---|---|---|
| `api-gateway` | HTTPS 路由、JWT 校验、限流 | 无状态 | Nginx/HAProxy |
| `user-service` | 登录、资料、好友(v1.5) | 无状态 | NestJS |
| `shop-service` | 充值、订单回调 | 无状态 | NestJS |
| `match-service` | 快速开始、官方场分配 | 无状态 | NestJS |
| `room-server` | WebSocket、状态机、结算 | **有状态** | NestJS + Socket.io + XState |
| `bot-engine` | GTO 决策 | 无状态 | Python gRPC |
| `admin-service` | 后台 CMS | 无状态 | NestJS |
| `risk-worker` | 筹码转移检测、定时对账 | 无状态 | Node worker |

> v1.0 可合并为 **api-service** + **room-server** + **bot-engine** 三个部署单元，降低运维复杂度。

## 三、Room Server 有状态路由

### 3.1 路由规则

1. 创建房间时，Match Service 选择负载最低 Room Pod
2. 写入 Redis：`room:pod:{room_id}` = `pod-ip:port`
3. Gateway 根据 `room_id` 一致性哈希 或 查 Redis 转发 WS

### 3.2 故障转移（v1.0 最小方案）

- Room Pod 崩溃 → K8s 重启 Pod
- 从 Redis `room:state:{room_id}` 恢复（AOF 持久化）
- 若 Redis 数据也在 → 本手牌作废，退还 antes/blinds 至各玩家 Redis 筹码，告警人工介入
- v1.1+ 引入 Room 主从热备

## 四、数据层修订

### 4.1 筹码类型

- `users.chips_balance`：**BIGINT UNSIGNED**（替换 DECIMAL）

```
对局中     → Redis only
END_HAND   → hand_histories + rake 流水（异步队列）
CASH_OUT   → MySQL 事务（chip_transactions + users）
```

## 五、Bot 引擎集成

### 5.1 接口定义（gRPC 草案）

```protobuf
service BotStrategy {
  rpc Decide(BotDecisionRequest) returns (BotDecisionResponse);
}

message BotDecisionRequest {
  string hand_id = 1;
  int32 seat_index = 2;
  repeated string hole_cards = 3;
  repeated string community_cards = 4;
  int64 pot_size = 5;
  int64 to_call = 6;
  int64 stack = 7;
  string position = 8;
  repeated ActionRecord action_history = 9;
}

message BotDecisionResponse {
  string action = 1;  // fold/check/call/raise/all_in
  int64 amount = 2;
  int32 think_time_ms = 3;  // 拟人延迟
}
```

### 5.2 SLA

- P99 延迟 < **800ms**
- 超时 fallback：`check` 或 `fold`（能 check 则 check）
- 每日预算：Redis `bot:budget:daily:{date}` 累加，超限降级

## 七、安全与鉴权

| 项 | 方案 |
|---|---|
| JWT Access | 2h |
| JWT Refresh | 30d，存 `user_sessions` |
| WS 连接 | `io({ auth: { token } })` |
| 底牌 | 按 socket 房间隔离下发；Redis 存明文，传输层 TLS |
| IP/设备互斥 | join_room 中间件 |
| Rate Limit | API 100/min/user；WS 30 actions/min/user |

## 八、可观测性

| 组件 | 方案 |
|---|---|
| 日志 | 结构化 JSON，字段：trace_id, user_id, room_id, hand_id |
| 追踪 | OpenTelemetry，`trace_id = hand_id` |
| 指标 | 在线人数、活跃桌数、P99 WS 延迟、Bot 调用延迟、rake 总量 |
| 告警 | Bot 预算耗尽、Redis 内存 >80%、Room Pod OOM、充值回调失败 |
