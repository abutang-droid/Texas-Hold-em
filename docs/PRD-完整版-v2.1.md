# 一、产品概述

## 1.1 产品定位

本产品是一款主打**联网多人实时对战**的德州扑克休闲竞技应用，面向 iOS、Android 及 Web 三端。

**核心差异化（三角）**：

| 维度 | 说明 |
|---|---|
| **单向封闭筹码经济** | 筹码仅官方 1:1 充值或活动赠送；不可兑换法币、不可玩家间转移 |
| **拟物化沉浸 UI** | 高质感牌桌、筹码堆叠、发牌/下注动效，还原实体牌桌体验 |
| **智能补位机制** | 官方场 5 秒内保证开局；低峰期由系统对手补位（v1.0 规则型，v1.5+ GTO） |

> **对外话术**：统一使用「智能补位对手」，避免 v1.0 承诺「GTO 最高智能」。用户协议中说明：官方场可能匹配系统安排的对手。

## 1.2 目标用户

| 用户类型 | 特征 | 核心需求 | 主要场次 |
|---|---|---|---|
| **休闲玩家** | 碎片时间、重体验 | 快速开局、界面好看、操作简单 | 官方场 |
| **社交竞技玩家** | 追求荣誉与积累 | 排行榜、好友局、筹码成长 | 官方场 + 私人场 |

## 1.3 核心 KPI

| 指标 | 缩写 | 目标 | 首阶段可达（v1.0 内测） |
|---|---|---|---|
| 开局等待时间 | Lobby Wait | ≤ 5 秒 | ≤ 5 秒 |
| 日均在线时长 | Session | ≥ 25 分钟 | ≥ 15 分钟 |
| 次日留存 | D1 | ≥ 40% | ≥ 25% |
| 月活 | MAU | 持续增长 | 内测基线 |
| 付费用户收益 | ARPPU | 持续提升 | v1.1 建立基线 |

# 三、经济规则

## 3.1 核心原则：单向封闭

- **唯一获取路径**：官方充值（1:1）或运营赠送
- **红线**：不可兑换法币；禁止玩家间转移（无赠送、交易、红包）
- **筹码精度**：全产品仅使用**整数筹码**（BIGINT 存储）

## 3.2 新用户经济与破产处理

### 注册赠送（v1.0 起）

| 项 | 规则 |
|---|---|
| 数额 | 首次注册赠送 **100 筹码**（一次性） |
| 流水类型 | `EVENT_GIFT`，`reference_id=REGISTER_BONUS` |
| 限制 | 每设备/每 OAuth 账号仅一次；游客转正后不重复发放 |
| 目的 | 降低首局门槛，不破坏单向经济（非每日低保） |

### 破产状态

当余额 < 当前场最低带入时，进入破产状态：

1. 弹出**分层引导弹窗**：
   - 主 CTA：「充值」（跳转商城）
   - 次 CTA：「返回大厅」（v1.0 可看等级/周榜）
2. **不提供**：每日低保、签到救济、自动补助
3. **不提供**：0 筹码旁观（v1.0）

## 3.3 充值与支付

### 支付渠道分阶段

| 版本 | 渠道 | 说明 |
|---|---|---|
| v1.0 / v1.0.5 | **模拟支付** | `POST /api/v1/shop/mock-recharge`，仅 `PAYMENT_MODE=mock` |
| v1.1 | Apple IAP、Google Play | 1:1 到账 |
| v2.0 | Stripe、USDC（World App） | Web 端 |

### 模拟支付规则（内测）

- 玩家输入金额 → 即时 1:1 到账
- 执行单日 **50,000** 筹码充值上限
- 生产环境返回 **403**
- 流水：`type=RECHARGE`，`channel=MOCK`
- UI 标注「测试筹码」水印（内测包）

### 内测 → 公测筹码迁移（v1.1 前）

- **推荐方案**：公测清零，重新注册赠送 100 筹码，提前 7 天公告
- **备选方案**：mock 充值部分 ×0.1 折算，需用户勾选确认

### 充值通用规则

- 比例：**1:1**（1 USD/USDC = 1 筹码）
- 自由输入金额，无固定套餐
- 运营赠送池：首充赠送等通过独立弹窗展示，UI 不显示折扣标签

## 3.4 抽水机制（Rake）

| 场次 | 比例 | 上限 | 触发条件 |
|---|---|---|---|
| 官方场 | **5%** | 无 cap | No Flop, No Drop |
| 私人场 | **3%** | 无 cap | 同上 |

- 尾数：**向下取整**（floor）
- 示例：底池 25 → rake = floor(1.25) = **1**

### 新手保护（v1.1 运营可选）

- 新注册用户前 **7 天**官方场 rake **减半（2.5%）**
- 后台 `system_config` 开关控制，内测期可 A/B

## 3.5 经济熔断

| 规则 | 阈值 | 动作 |
|---|---|---|
| 单日充值限额 | 50,000 筹码 | 拒绝充值 |
| 大额波动 | 1h 内 ±10,000 | 告警 + 冻结高注私人场权限 |
| Bot 日亏损预算 | 500,000 筹码 | Bot 仅 Check/Fold + 告警 |

```
└─────────────────────────────────────┘
  * v1.0 仅周榜 Top10；v1.1 完整排行榜
```

## 5.2 场次类型

| 类型 | 盲注 | 带入 | Bot | Rake | 上线版本 |
|---|---|---|---|---|---|
| **官方场** | 固定 1/2 | 动态 cap | ✅ 规则型 | 5% | v1.0 |
| **私人场** | 房主配置 | 房主配置 | ❌ | 3% | v1.0.5 |

## 5.3 官方场

### 桌配置

| 项 | 值 |
|---|---|
| 座位数 | **9 人桌**（椭圆布局） |
| 开局条件 | ≥ **2** 人 seated |
| 观战 | v1.0 不支持 |

### 动态带入上限

公式：当 ≥2 人（含 Bot）筹码 **严格大于** `100 × 2^n` 时，新带入上限 = `100 × 2^(n+1)`

| 触发（≥2 人筹码 >） | 带入上限 |
|---|---|
| — | 100 |
| 500 | 200 |
| 1,000 | 400 |
| 2,000 | 800 |
| 4,000 | 1,600 |
| 继续翻倍 | 继续翻倍 |

- 已在桌玩家不受上限约束

### 快速开始与匹配

1. 点击「快速开始」
2. 优先匹配 **真实玩家 ≥2** 的官方桌
3. 无合适桌 → 创建新桌 → 启动 **5 秒**计时器
4. 5 秒后真实玩家 <3 → 补 Bot 至 3 人（单桌 Bot ≤**6**，至少 1 真实玩家）
5. 真实玩家 ≥**4** 的桌子**不再补 Bot**
6. 满 **9** 人 → 下局开始前 Bot 自然退场（当前手牌结束后）

## 5.4 私人场（v1.0.5）

### 开房权限

- 一次性 **100 筹码**开通，永久有效
- 勾选《私人房间合规使用协议》，存证 IP/UA/时间

### 建房配置

| 字段 | 范围 |
|---|---|
| 人数上限 | 2–9 |
| 盲注 | 如 1/2、5/10、10/20（房主选） |
| 带入上限 | 10–10,000（房主选） |

### 2 人局限制（合规）

- 2 人私人局：房主须完成 **≥10 局**官方场
- 系统记录并校验

### 筹码与 Re-buy

- 筹码仅来自个人账户官方筹码
- Re-buy 需房主审批，**60 秒**超时自动拒绝
- 房主离线 >5 分钟：Re-buy 自动拒绝

### 组局 UX（v1.0.5 必须）

**建房成功页**：

```
┌─────────────────────────────────┐
│  房间号：882916    [复制]        │
│  盲注：5/10  上限：500           │
│                                 │
│  [分享给好友]  [复制邀请文案]     │
│                                 │
│  邀请文案示例：                  │
│  「来打德州！房间号 882916       │
│    盲注 5/10，点击加入 → [链接]」│
└─────────────────────────────────┘
```

| 能力 | 规格 |
|---|---|
| 房间号 | 6 位数字，全局唯一 |
| 深链接 | `texasholdem://room/882916`（v1.0.5） |
| 分享 | 系统 Share Sheet（iOS/Android） |
| 加入 | 大厅输入房间号 或 点击链接 |

### 房主管理权限

| 权限 | 规则 | 版本 |
|---|---|---|
| 踢人 | 当前手牌结束后生效 | v1.0.5 |

# 六、对战规则

## 6.1 标准流程

无限注德州（No-Limit Hold'em）：

`Pre-flop → Flop → Turn → River → Showdown`

- 新玩家等 BB 或 Post Blind 立即参与
- Button 顺时针移动

## 6.2 行动与时间

| 规则 | 值 |
|---|---|
| 操作时间 | **15 秒** |
| 最后 5 秒 | 急促音效 + 红框闪烁 |
| 超时 | Check（可 check 时）或 Fold |
| 连续 2 次超时 | Sit Out 5 分钟 |
| 预操作 | 自动弃牌 / 自动过牌或弃牌 / 跟任何注 |

## 6.3 边池与平局

- All-in 触发边池，结算从最后一个边池向前
- **Chop 奇数筹码**：分配给 Button 顺时针第一个未弃牌且仍有资格争池的玩家

## 6.4 留座与断线

| 场景 | 处理 |
|---|---|
| 主动暂离 | 保留座位 5 分钟，超时筹码退回 |
| 断线 | 等同暂离；重连后 `room_state_sync` 恢复 |

## 6.5 聊天规则

| 场次 | 聊天 |
|---|---|
| 官方场 | 仅 **Emoji 快捷语**（8–12 个预设） |
| 私人场 | 文字 + Emoji |

## 6.6 UI 约束

- 拟物化（Skeuomorphic），禁止魔法特效
- 筹码飞入抛物线 + 阻尼感
- 9 人桌椭圆布局，当前行动玩家高亮

# 七、智能补位对手（Bot）

## 7.1 设计目标

保证**任何时段 5 秒内开局**，解决冷启动与低峰空桌。

## 7.2 触发与退场

| 条件 | 动作 |
|---|---|
| 新桌 5s 后真实玩家 <3 | 补 Bot 至 3 人 |
| 真实玩家 ≥4 | 不补 Bot |
| 满 9 人 | 下局开始前 Bot 退场（当前手牌结束后） |
| 单桌 Bot 上限 | **6**；至少 **1** 真实玩家 |

## 7.3 策略分阶段

| 版本 | 策略 | 实现 |
|---|---|---|
| v1.0 | **规则型** | Room Server 内置：位置 + pot odds + 牌力表 + 3–5% 失误 |
| v1.5+ | **GTO** | Python gRPC 引擎 |

### 规则型 Bot 要点（v1.0）

- Preflop：位置 + 手牌强度表
- Postflop：底池赔率 + 简化牌力
- 风格：略偏 loose-passive（娱乐性优先）
- 延迟：1–5s（复杂 3–8s）
- 拟人：随机昵称/头像、随机 Emoji

## 7.4 拟人化

| 维度 | 规范 |
|---|---|
| 身份 | 真实头像库 + 昵称（如 Mike_D） |
| 延迟 | 1–5s，复杂决策 3–8s |
| 失误 | 3–5% 非最优 |
| 披露 | 不主动披露；协议中说明可能有系统对手 |

## 7.5 经济隔离

- Bot 使用虚拟筹码，与玩家池隔离
- Bot 赢 → 系统回收销毁
- Bot 输 → 隐性福利给真实玩家
- 日亏损预算：**500,000** 筹码，超限 Bot 只 Check/Fold

# 九、等级与排行榜

## 9.1 等级系统

### 经验获取

| 行为 | EXP |
|---|---|
| 参与一局（看到翻牌） | +1 |
| 赢得底池（>5BB） | +5 |
| 葫芦 | +50 |
| 四条 | +200 |
| 同花顺 | +500 |

### 等级公式

`升到 Lv.N 所需累计 EXP = floor(50 × N^1.5)`

- v1.0：展示 Lv 数字 + 进度条
- v1.5：头像框材质（每 10 级）

## 9.2 排行榜

| 版本 | 范围 |
|---|---|
| v1.0 | **本周盈利 Top 10**（大厅展示前 3） |
| v1.1 | 盈利榜 + 单局最高榜，每 10 分钟刷新，周一 0:00 重置 |

# 十一、技术规格（产品约束）

| 模块 | 要求 |
|---|---|
| 实时通信 | WebSocket (Socket.io)，延迟 ≤100ms |
| 权威模型 | 服务端洗牌、比牌、结算；客户端仅渲染 |
| 并发 | 单 Room Server Pod：200 桌 / ~1800 连接（9 人桌） |
| 持久化 | 对局 Redis；END_HAND 写 hand_histories；离桌写 **PostgreSQL** |
| 数据库 | **PostgreSQL 16** + Redis 7 |
| 支付 | v1.0 mock；v1.1 IAP |
| 底牌安全 | per-player 通道；Showdown 明文广播 |
| 断线重连 | State Snapshot |

> 技术细节见 `06-架构补充修订-v1.1.md`、`04-WebSocket协议规范.md`
